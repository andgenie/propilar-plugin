# Propilar で物件を分析する

Propilar の MCP サーバ（`https://mcp.propilar.com/mcp`）のツールを使い、不動産投資の初心者にも分かる言葉で物件を評価する。数字の計算は必ずツールに任せ、自分で暗算しない。

## 前提

- ツール `analyze_property` などが見えないときは、Propilar の MCP サーバが未接続か未ログイン。接続方法（このプラグインのインストール、または MCP 設定に `https://mcp.propilar.com/mcp` を追加し、ブラウザで Propilar にログイン）を案内して止まる
- 無料プランは分析系ツールが月30回まで（成功した呼び出しだけ数える）。1回の相談でツールを呼びすぎない（基本は `analyze_property` 1回、必要なときだけ追加）
- 結果は投資助言ではない。「買うべき」「買うべきでない」と断定しない

## 手順

1. **入力を集める** — 必須は 購入価格・想定月額家賃（満室）・借入額 の3つ。分かれば 金利・返済年数・構造・築年月・空室率 も聞く。聞き方と既定値は [references/inputs.md](references/inputs.md)
   - 単位を変換して渡す: 万円 → 円（4,000万円 → `40000000`）、% → 小数（2% → `0.02`）
   - 物件種別（区分マンションか）と築年は、判定の限界を伝えるのに使うので必ず確認する
2. **分析する** — `analyze_property` を呼ぶ。保存はしない
3. **結果を説明する** — 判定ラベルと理由を先に、次に効いている指標を2〜3個だけ。読み方は [references/judgement-guide.md](references/judgement-guide.md)
4. **必要なら深掘りする**（ユーザーの関心に合わせて1つずつ）
   - 「金利が上がったら」「空室が増えたら」→ `stress_test`
   - 「自己資金をいくら入れるか」「金利と空室の組み合わせ」→ `run_sensitivity_matrix`（例: 行 `ltv` × 列 `interest_rate`、指標 `btcf`）
   - 条件違いの比較（ローン条件A/B、物件A/B）→ `compare_scenarios`（2〜5個）
   - 「何年持てばいいか」→ `run_irr_sensitivity`
5. **限界を伝える** — 該当するときは必ず一言添える
   - 区分マンション: 管理費・修繕積立金は入力できず、運営費は家賃の約10%で自動見積もり。実際の管理費等が高いと判定が甘く出る。正確に見たいときは結果の `analysisUrl`（propilar.com、条件入力済み）で管理費を入れ直してもらう
   - 築古（特に1981年5月以前の旧耐震、木造で築22年超など法定耐用年数を超えるもの）: 旧耐震・大規模修繕・残存耐用年数を超える融資期間は判定に入っていない。融資期間を残存耐用年数に合わせた条件でも `analyze_property` を回し、判定が変わるか確かめる
6. **保存は頼まれたときだけ** — 「保存して」と言われたら `create_property` → `create_scenario`（または既存シナリオに `save_analysis`）。自動で保存しない

## 説明のしかた

- 金額は「万円」、利回り・金利は「%」で話す（ツールの戻り値は円と小数）
- 専門用語は初出で言い換える（DSCR = 家賃収入でローン返済を何倍まかなえるか、など）
- 判定が「要確認項目あり」「リスク要因多い」のときは、どの条件を変えれば改善するか（価格交渉・自己資金・金利・返済期間）を、ツールで確かめたうえで1〜2個示す
- 最後に、結果は入力に基づく参考情報で、最終判断はユーザー自身が行うものだと添える
