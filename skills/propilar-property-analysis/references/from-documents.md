# 物件資料（PDF・画像・URL）から分析する

マイソク（販売図面）、物件概要書、レントロール、ポータルサイトの掲載ページなどから始めるときの手順。資料は自分（AI）で読み、読み取った数値を `analyze_property` に渡す。`import_property` は使わない（PDF・URL に非対応で、対応クライアントも限られるため）。

## 1. 資料を読む

- PDF・画像: そのまま読む。複数ページあれば概要・収支・レントロールのページをすべて見る
- URL: ページを取得して読む。取得できないとき（ログインが必要、自動取得を拒否されるなど）は、無理に別の手段を試さず「ページのスクリーンショットか PDF を貼ってください」と頼む
- 読めない・数字がかすれているところは推測で埋めず、「読み取れなかった」として後でユーザーに聞く

## 2. 読み取る項目

| 資料での表記の例 | 使い道 | 注意 |
|----------------|-------|------|
| 価格・販売価格 | `purchasePrice` | 「万円」表記を円に直す。税込みか確認（建物には消費税がかかる） |
| 満室想定賃料・想定年収 | `assumedMonthlyRent` | **年額なら12で割る**。「現況賃料」「現況年収」と別に書いてあれば、両方を控える |
| 表面利回り・想定利回り | 家賃の逆算・照合 | 家賃がなく利回りだけなら `価格 × 利回り ÷ 12` で月額家賃に直す。家賃と利回りが両方あれば計算が合うか確かめる |
| 構造（木造・軽量鉄骨・RC など） | `structureType` | 「鉄骨造」だけなら軽量か重量か聞く（厚さ4mm以下が軽量） |
| 築年月・完成年月 | `builtYearMonth` | 和暦は西暦に直す（平成27年 → 2015年） |
| 土地・建物の価格内訳 | `buildingPrice` / `landPrice` | 書いていなければ省略（既定の3:7） |
| 総戸数・空室数・入居率 | `vacancyRate` の参考 | 現況で空室があれば、満室想定賃料との差を説明する |
| 管理費・修繕積立金（区分マンション） | 分析には入らない | 金額を控え、限界の説明に使う（下記4） |
| 権利（所有権・借地権）、再建築不可、既存不適格、告知事項、私道負担 | 分析には入らない | 書いてあれば必ず伝える（下記4） |

借入条件（借入額・金利・返済年数）は資料に載っていないのが普通。ユーザーに聞く。分からなければ [inputs.md](inputs.md) の既定値を使い、そう伝える。

## 3. 分析の前に確認する

読み取った値を表で見せ、ユーザーに確認してもらってから `analyze_property` を呼ぶ。読み違いがあるとツールを呼んだ回数（無料枠）も無駄になる。

```
資料から次のように読み取りました。違っていれば教えてください。

| 項目 | 値 | 出典 |
| 価格 | 4,280万円 | 1ページ目「価格」 |
| 満室想定家賃 | 月35.6万円（年427.2万円） | 「想定年収」から換算 |
| 現況家賃 | 月29.8万円（6室中1室空き） | レントロール |
| 構造・築年 | 木造・2016年3月 | 物件概要 |
| 権利 | 所有権 | |

借入額・金利・返済年数を教えてください（金利と返済年数が未定なら 2%・20年 で試算します）。
```

満室想定と現況が違うときは、まず満室想定で分析し、続けて現況家賃でも分析して差を見せる（空室が埋まらなかった場合に収支がどうなるか）。

## 4. 結果と一緒に伝えること

資料に書いてあったのに分析に入っていないものを、結果の後に必ず添える。

- 区分マンションの管理費・修繕積立金: 「資料では管理費等が月◯万円。分析では運営費を家賃から自動で見積もっているため、この金額は入っていません」。正確に見たいときは結果の `analysisUrl`（propilar.com、条件入力済み）を開いて管理費を入れてもらう
- 借地権: 地代の支払いがあり、融資が付きにくく売却も難しくなる
- 再建築不可・既存不適格: 融資が付きにくく、建て替えや売却に制約がある
- 告知事項: 内容によって賃料や売却価格に影響する
- 旧耐震（1981年5月以前の建築確認）・築古: 判定に入っていない（SKILL.md の手順5）

資料の数字は売主・仲介会社の提示値で、満室想定賃料は相場より高めに書かれていることがある。気になるときは周辺の賃料相場を確かめるよう添える。
